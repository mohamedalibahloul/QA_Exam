Test Case Plan: This document lists all 102 planned automated test cases for the Maison Lumen Cart & Promo Code API, executed with pytest (Python). It is the planning document — execution results, defects, summary and approval are recorded later in the release document.

Software Test Case Sheet · Maison Lumen Cart & Promo API

HYD-TCS-QA-001 · v1.3

Overview

I derived 102 test cases directly from the specification (SPEC.md), covering ten functional areas: Catalogue, Cart creation & reading, Quantities, Stock, Totals & shipping, Promo codes, Checkout, Order status, Concurrency and Unclear spec points. Each case is named stc-<module>-<NN>-<short description> and traces back to a spec rule. Cases tagged @proposed in the ambiguous module cover places where the spec is silent — a failure there must be discussed with the spec author before it is reported as a bug.

Test Case Naming Convention

stc-<module>-<NN>-<short description>
  • stc — Spec Test Case (every case is derived from SPEC.md).
  • <module> — functional module: prod (catalogue), cart, item (quantities), stock, tot (totals & shipping), promo, chk (checkout), ord (order status), conc (concurrency), amb (ambiguous).
  • <NN> — sequence number within the module.
  • <short description> — what the case asserts, in one phrase.
  • Example: stc-promo-09-second discount refused = Spec Test Case, Promo module, case 9, asserting that a second discount code is refused.
