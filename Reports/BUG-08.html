Title *
Adding exactly the available stock is refused
Reporter *
Dalii · QA
Bug Overview
Summary *
Adding 3 Reed Diffusers (stock 3) in one request returns 409. Adding 1, then changing to 3, works.
Module / Class *
POST /carts/{id}/items · stock check (tests/test_stock.py)
Category *
Stock
Layer *
Backend / API
Technical Environment
Environment
Local server (node server.js, port 3002)
Platform
REST API (Node.js)
Test Duration
stc-stock-01: 10 ms
Defect Details
Precondition *
Server freshly reset. Reed Diffuser Set (id 4) priceCents 3990, stock 3.
Steps to Reproduce *
Add exactly the stock
  1. curl -X POST http://localhost:3002/reset
  2. curl -X POST http://localhost:3002/carts
  3. curl -X POST http://localhost:3002/carts/c1/items -H "Content-Type: application/json" -d '{"productId": 4, "quantity": 3}'
Workaround: add 1 then change to 3
  1. curl -X POST http://localhost:3002/reset
  2. curl -X POST http://localhost:3002/carts
  3. curl -X POST http://localhost:3002/carts/c1/items -H "Content-Type: application/json" -d '{"productId": 4, "quantity": 1}'
  4. curl -X PATCH http://localhost:3002/carts/c1/items/4 -H "Content-Type: application/json" -d '{"quantity": 3}'
Expected Result *
  • 201, and the line holds 3 units.
Actual Result *
  • 409 {"error":"Not enough stock"}.
Error / Stack Trace
POST /carts/c1/items -> HTTP 409
{"error": "Not enough stock"}
Impact *
Customers cannot buy the last units in one step. The rule is inconsistent between POST and PATCH. No wrong data is stored.
Classification
Severity *
High A rule is broken but a workaround exists.

Recommendation
Suggested Fix *
Refuse only when quantity is strictly greater than the stock.

Possible cause: The add handler compares with >= instead of >.
Spec reference: SPEC §3, rule 3: “Exactly the stock is allowed. Above: 409.”
