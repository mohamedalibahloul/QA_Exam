Title *
Two checkouts at the same time make the stock negative

Bug Overview
Summary *
Two carts that each hold the 2 last vases both check out successfully when the requests arrive together. The stock ends at -2.
Module / Class *
POST /carts/{id}/checkout · stock update (tests/test_concurrency.py)
Category *
Stock / Concurrency
Layer *
Backend / API
Technical Environment
Environment
Local server (node server.js, port 3002)
Platform
REST API (Node.js)
Test Duration
stc-conc-01: 85 ms · stc-conc-02: 91 ms
Defect Details
Precondition *
Server freshly reset. Hand-blown Vase (id 6) has stock 2. Two carts c1 and c2 each hold 2 vases (added with 1, then changed to 2, because adding 2 in one request hits BUG-08).
Steps to Reproduce *
Two simultaneous checkouts of the last 2 vases
  1. curl -X POST http://localhost:3002/reset
  2. curl -X POST http://localhost:3002/carts
  3. curl -X POST http://localhost:3002/carts
  4. curl -X POST http://localhost:3002/carts/c1/items -H "Content-Type: application/json" -d '{"productId": 6, "quantity": 1}'
  5. curl -X PATCH http://localhost:3002/carts/c1/items/6 -H "Content-Type: application/json" -d '{"quantity": 2}'
  6. curl -X POST http://localhost:3002/carts/c2/items -H "Content-Type: application/json" -d '{"productId": 6, "quantity": 1}'
  7. curl -X PATCH http://localhost:3002/carts/c2/items/6 -H "Content-Type: application/json" -d '{"quantity": 2}'
  8. Send at the same time (two terminals or &):
    curl -X POST http://localhost:3002/carts/c1/checkout
    curl -X POST http://localhost:3002/carts/c2/checkout
  9. curl -X GET http://localhost:3002/products/6
Expected Result *
  • One checkout returns 201, the other 409.
  • Stock of product 6 is 0.
Actual Result *
  • Both checkouts return 201.
  • GET /products/6 returns "stock": -2.

Impact *
The shop sells goods it does not have. Both customers are told the order is confirmed, and one of them will have to be refused or refunded later. With 5 carts, 5 orders are accepted for a stock of 2 (stc-conc-02).

Recommendation
Suggested Fix *
Make the check and the decrease one atomic step: no await between them, or a lock per product. Re-check the stock at the moment of decrease and return 409 when it is not enough.

Possible cause: Checkout checks the stock, then waits (await sleep(25) in server.js) before decreasing it. A second request passes the check during that wait.
Spec reference: SPEC §6: “The stock can never become negative, including when two customers check out at the same time.”
